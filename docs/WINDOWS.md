# Windows download

Jarvis 0.8.0 is a self-contained Windows 10/11 x64 executable. Download it from the public site and open it. It extracts once, opens the native desktop companion, and creates desktop and Start menu shortcuts. No terminal, Node installation, npm installation, or administrator access is needed.

Press **Ctrl+Shift+Space** to summon the companion. It starts as a compact conversation panel and opens the existing full workbench only after you select a build or Computer mode workflow. The companion requires the Microsoft Edge WebView2 Runtime; Jarvis checks for it and gives an installation path when it is unavailable.

Choose Astra or Fable and an effort level in the workbench. Sign-in is a button in Setup and uses the selected official CLI’s browser flow. Codex is bundled. For Fable, Setup downloads and verifies official Claude Code 2.1.261 with one install button; Anthropic binaries are not redistributed inside the executable. Subscription entitlement and limits still apply, and Fable can consume paid usage credits. There is no API key or paid API fallback. Closing the companion leaves Jarvis in the notification tray; **Quit Jarvis** stops its owned process tree. Reopening the shortcut opens the existing session. If another application occupies port 4317, Jarvis shows an error instead of trusting that application.

The launcher is unsigned. Windows may display an unknown-publisher warning. The release provides SHA256SUMS.txt, and the build verifies the included Node and Codex upstream publishers. A checksum detects a changed download; it is not a publisher signature.

## Updates and removal

Quit Jarvis from its tray menu, then open the new download. Each build extracts into a separate directory under `%LOCALAPPDATA%\Jarvis\versions`; shortcuts point to the new version. Saved work stays in Jarvis's persistent desktop profile. A source-development browser profile or an older browser-based install is separate, so its revisions are not imported automatically. Export HTML you want to retain, then use **Settings → Import a saved HTML prototype** in the companion. Imports are limited to 120,000 bytes and append a revision only when the 12-version history has room. Older extracted versions are retained, and opening an old download restores its shortcut after quitting the current version.

To remove Jarvis, quit it, then use File Explorer to remove its shortcuts and its Jarvis folder in local application data. Desktop-profile projects and the official Codex account login are separate: **New project** clears the current saved project; removing Jarvis does not sign out or erase another Codex installation's credentials.

## Developer packaging

After building, run `powershell -NoProfile -File scripts/verify-desktop-host.ps1` and `node scripts/verify-desktop-content.mjs` with Jarvis quit. The first checks the real panel, dock, shortcut registration and reopening. The second uses an isolated desktop profile and a temporary localhost debugging connection to verify the embedded interface, prototype interaction, download, synthetic camera and a dedicated capture fixture. It makes no model requests. Debugging is not enabled by normal launches.

Run `npm run build:windows` on Windows x64 with Node 24, npm and the installed .NET Framework C# compiler. The script downloads Node 24.15.0 and official Codex 0.153.4 using pinned integrity values, checks upstream publisher signatures, and embeds a fixed allowlist of app files into a WinForms launcher. A fresh staging directory prevents old files leaking into a later package. Upstream license notices are included. No local profile, credential file or user revision is packaged.

Run `npm run verify:windows` to exercise extraction with a system-only PATH, bundled CLI discovery, an explicitly isolated signed-out CLI status probe, desktop session protection, and rendered setup/preview/reload behavior. Windows account-level authentication can survive HOME overrides; the packaged server check does not claim a new OS account or alter the existing login. No model call is made. With port 4317 free, run `powershell -NoProfile -File scripts/verify-windows-lifecycle.ps1` to check occupied-port refusal, repeated launches, Quit and forced-exit cleanup. These checks render the embedded app. The release assets are `Jarvis-0.8.0-Windows-x64.exe` and `SHA256SUMS.txt` under `.artifacts/windows-0.8.0`. Publish both only after verifying the final build.

The transient `JARVIS_DESKTOP_KEY` is generated by the launcher and passed only to its Node child. It is not a user setting and must not be stored in an environment file. Node consumes and removes it immediately. The browser strips its fragment from the visible URL, keeps the key in session storage scoped to the exact origin including the port, and sends it only in an API header. No authentication cookie is used. Never log the launch URL or process environment.

## Computer control

Version 0.8 bundles the Windows accessibility controller source and its PowerShell launcher; no extra installation is required. The companion can suggest opening Computer mode, but only the explicit workflow button opens it and its existing consent and per-action review gates still apply. Ctrl+Shift+F12 must be available before the session can arm. Other Jarvis Computer sessions using that shortcut must be stopped first. Protected windows and apps without supported accessibility patterns refuse actions. See [Computer mode](COMPUTER.md).
